# Kioku の UI 規約

Kioku のモーダル UI（候補選択・デッキ選択・復習画面）に共通する見た目と操作の約束。個別画面の詳細は次を参照し、この文書はそれらに共通する規則だけを置く。

- 候補選択画面: `docs/candidate-selection-ui.md`
- デッキ選択と復習画面の仕様・保存の安全策: `docs/m2-design.md`
- 実機確認の手順（専用インスタンスだけ）: `docs/harness.md`

## 1. Obsidian 標準を最優先する

- 色・字体・余白・角丸・影は Obsidian の CSS 変数だけを使う（`--text-muted`、`--text-error`、`--background-modifier-border`、`--background-modifier-hover`、`--size-4-*`、`--radius-*`、`--font-ui-*`、`--font-text-size` など）。新しく固定の色・フォントを足さず、余白・角丸・文字サイズも変数で指定する。今回の例外は 1px の枠線、スキップの `:focus-visible` の 3px のフォーカス枠（Obsidian 本体と同じ値）、キーバッジの `opacity`・`line-height: 1.4`、折り返しの閾値（`16rem`・`27rem`）。それ以前からある固定値（メニュー幅 `min-width: 180px`、問題文・答えの `max-height: 30vh`、メニュー項目の 2px の outline と無効時の `opacity: 0.5` など）はそのまま残している。明/暗テーマとユーザーのフォント設定はこれで追従する。
- アイコンは `setIcon`（Lucide の標準アイコン）で描き、アイコンだけのボタンには `clickable-icon` を付けて見た目（hover・押下中の `is-active`・フォーカス枠）を Obsidian に任せる。絵文字や記号文字（⚙ など）をアイコンの代わりにしない。
- 標準ボタンの見た目を弱める（背景・影を消す）ときは、キーボードのフォーカス枠（`:focus-visible` の `box-shadow: 0 0 0 3px var(--background-modifier-border-focus)`）を必ず戻す。
- ボタン・モーダル・タイトルは Obsidian 標準の要素（`Modal#setTitle`、`button`、`mod-cta`、`mod-warning`）を使い、独自の部品を増やさない。
- スタイルは `styles.css` にモーダルのルートクラス（`.kioku-deck-picker-modal` など）で範囲を限って書く。

## 2. 階層: 主役は1つ、補助は控えめ

- 各状態で強調する主要操作（`mod-cta`）は最大1つ（完了画面は強調なし）。例: 復習画面の出題中は「答えを表示」、答え表示中は「普通」、保存失敗中は「もう一度保存する」だけ（失敗中は「普通」の強調を外す）。
- スキップのような補助操作は背景なしの控えめなボタンにし、行の先頭（左）に置く。単独の主要操作（「答えを表示」「もう一度保存する」）は行の末尾（右）。評価ボタンは 1〜4 の順に並べ、強調は「普通」に付ける。
- 同じ情報を2回出さない。復習画面ではデッキ名はモーダルのタイトルだけに出し、上部の行は「残り N 枚」とメニュー（歯車）だけにする。
- 内容（問題文）を最も大きく読む対象にする。問題文は `--font-text-size` の 1.2 倍、答えは本文サイズ、両者は細い区切り線で分ける。

## 3. ショートカット表示

- キー操作できるボタンは、ラベルの後ろに同じ形のキーバッジ（`.kioku-review-key`）を付ける。括弧書き「（S）」と混在させない。
- バッジは `aria-hidden="true"` にして読み上げ対象から外し、ボタンに `aria-keyshortcuts` を付ける。評価ボタンは `aria-label` にもキーを含めるので、ショートカットを読み上げる支援技術ではキー名が2回聞こえることがある（実機の読み上げは未確認）。
- 評価ボタンは「ラベル + キー」と「次回の間隔」を2段で示す。`aria-label` には「普通（キー 3）：次回 3日後」のように全部を含める。

## 4. 状態の表示

- 保存中・保存失敗は、評価ボタンの行とスキップの行の間にある状態行（`.kioku-review-status`）に出す。保存中は控えめな色、失敗は `--text-error`。失敗時の再試行ボタンは同じ行の末尾に置き、フォーカスを移す。
- 保存中・失敗中は評価・スキップ・メニュー項目を無効にする（`disabled`）。見た目だけでなく `handleKey` 側でも受け付けない。
- 読み取り専用などの注意は `--text-warning` で上部に出す。
- 対象がない操作は無効表示で残さず、出さない（例: 完了画面ではカードに依存するメニューを出さない）。

## 5. キーボードとフォーカス（変更してはいけない約束）

- キー入力は `ReviewScreen#handleKey` の1経路だけで処理する。Space/Enter はフォーカス中の Kioku ボタンに対して1回だけ働き、ネイティブのクリックと二重に発火しない。キーリピート・IME 変換中・修飾キー付きは無視する。
- Escape はメニューが開いていればメニューだけを閉じてフォーカスを歯車に戻し、閉じていればモーダルを閉じる（Obsidian の Scope 経由。二重発火させない）。
- 描画のたびに、その状態の主要操作へフォーカスを置く。主要操作が押せない間（保存中、読み取り専用で答えを表示中など）は画面ルート（`tabIndex = -1`）に置き、フォーカスをモーダルの外へ逃がさない。
- 例外: メニューを開いた直後は先頭のメニュー項目（無効なら主要操作、それも無ければ歯車）、メニューを閉じた直後は歯車に置く。完了画面は強調する主要操作が無いので、最初の「今日だけ あと N 枚」、無ければ「デッキ選択に戻る」に置く（処理中は画面ルート）。
- これらは `tests/ui/review.test.mjs` の回帰テストで固定している。見た目の変更でクラス名や DOM 順を変えるときはテストも更新する。

## 6. 幅と長文

- モーダル幅は画面ごとに `min(<幅>, <画面比>)` で決める（起動 `min(32rem, 90vw)`、候補選択 `min(48rem, 92vw)`、デッキ選択・復習 `min(44rem, 92vw)`）。
- 評価ボタンのラベルは途中で折り返さない（`white-space: nowrap`）。評価ボタンは復習画面の幅（コンテナクエリ `kioku-review`）が 27rem 以下なら 2 列×2 段に切り替える。
- 問題文・答えは `overflow-wrap: anywhere` で折り返し、長いときはそれぞれの領域内でスクロールする（`max-height: 30vh`）。

## 7. 確認のしかた

- UI の変更は `npm run check` に加え、専用 Vault の実機（`harness:launch` / `harness:quit`）で明/暗・長文・狭幅を見て `artifacts/` に証跡を残す。モックやファイル検査の成功を実機成功と呼ばない。
- 実機確認は合成データだけを使い、利用者の Vault や Obsidian には触れない。
