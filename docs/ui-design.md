# Kioku の UI 規約

Kioku のモーダル UI（候補選択・デッキ選択・復習画面）に共通する見た目と操作の約束。個別画面の詳細は次を参照し、この文書はそれらに共通する規則だけを置く。

- 候補選択画面: `docs/candidate-selection-ui.md`
- デッキ選択と復習画面の仕様・保存の安全策: `docs/m2-design.md`
- 実機確認の手順（専用インスタンスだけ）: `docs/harness.md`

## 1. Obsidian 標準を最優先する

- 色・字体・余白・角丸・影は Obsidian の CSS 変数だけを使う。デッキ選択・復習画面の例外は下の「本人が承認した例外（LEV-321）」（変数の例: `--text-muted`、`--text-error`、`--background-modifier-border`、`--background-modifier-hover`、`--size-4-*`、`--radius-*`、`--font-ui-*`、`--font-text-size` など）。新しく固定の色・フォントを足さず、余白・角丸・文字サイズも変数で指定する。今回の例外は 1px の枠線、`:focus-visible` の 3px のフォーカス枠（Obsidian 本体と同じ値。デッキの行と評価ボタンで使う）、キーバッジの `opacity`・`line-height: 1.4`、折り返しの閾値（`16rem`・`27rem`）。それ以前からある固定値（メニュー項目の 2px の outline と無効時の `opacity: 0.5` など）はそのまま残している。歯車のメニュー幅は調整台に合わせて `min-width: 200px`。明/暗テーマとユーザーのフォント設定はこれで追従する。
- アイコンは `setIcon`（Lucide の標準アイコン）で描き、アイコンだけのボタンには `clickable-icon` を付けて見た目（hover・押下中の `is-active`・フォーカス枠）を Obsidian に任せる。絵文字や記号文字（⚙ など）をアイコンの代わりにしない。
- 標準ボタンの見た目を弱める（背景・影を消す）ときは、キーボードのフォーカス枠（`:focus-visible` の `box-shadow: 0 0 0 3px var(--background-modifier-border-focus)`）を必ず戻す。
- ボタン・モーダル・タイトルは Obsidian 標準の要素（`Modal#setTitle`、`button`、`mod-cta`、`mod-warning`、`Menu`）を使い、独自の部品を増やさない。例外: デッキ選択・復習画面は上部の行（`.kioku-modal-header`）を自分で描く（⋯・歯車を Obsidian の × の左隣に置き、復習画面ではタグと進捗を中央に出すため）。Obsidian の空の `.modal-header` は隠し、× は Obsidian のもの（1.14 は `.modal-header-button`、それより前は `.modal-close-button`）をそのまま使って上部の行の右端にそろえる。行の右端には × の分の空き（`.kioku-modal-close-space`）を置く。
- スタイルは `styles.css` にモーダルのルートクラス（`.kioku-deck-picker-modal` など）で範囲を限って書く。

### 本人が承認した例外（LEV-321、2026-10-07）

デッキ選択と復習画面は、本人が調整台で決めた値を固定の色・寸法として使う。値は `.kioku-deck-picker-modal` に CSS 変数で置き（`--kioku-deck-*`、`--kioku-review-*`、`--kioku-progress-*`、`--kioku-question-*`、`--kioku-answer-*`、`--kioku-qa-label-*`、`--kioku-divider-*`、`--kioku-rating-*`。名前は調整台の HTML と同じ）、規則はそれを参照する。

- デッキ選択: 幅 560px・角丸 14px、上部の上下余白 8px、本文の余白 15px、行の高さ 40px・角丸 8px、デッキ名 15px、件数 13px、件数の列 56px・間隔 8px、見出しの上 20px・下 11px、見出しの下は破線。件数と列見出しは色付き（新規 `#4f8fd6`、学習中 `#c8574f`、復習 `#5f9a46`）、0 件は `--text-faint`。
- ホバーの背景は承認値 `#2f2f2f`（暗いテーマ用）。明るいテーマ（`.theme-light`）では濃すぎるので `--background-modifier-hover` に置き換える。復習画面の区切り線の色 `#3f4747` も同じ理由で、明るいテーマでは `--background-modifier-border` にする。
- 復習画面: 幅 820px・角丸 16px（狭い画面では 100% に縮む）、上部の上下余白 11px・左右 14px、アイコン 28px、上部の下に 1px の線。進捗表示は色付きの角丸ピル（背景 `#1f7a7a`、文字 `#ffffff`、15px、角丸 12px、太字、区切りは縦線）。本文の余白 24px、「問題」「答え」の見出し 12px・`#8c8c8c`・太字、問題文と答えは同じ 17px、区切り線は 1px 実線。
- 評価ボタンは色付き（もう一度 `#c8574f`、難しい `#b8892f`、普通 `#22807f`、簡単 `#3f7fcf`、白文字）、高さ 60px・角丸 10px・間隔 14px・文字 16px。「答えを表示」は Obsidian のアクセント色（`mod-cta`）で、評価ボタンと同じ高さ・角丸。
- 色付きのボタンと行は背景を自分で塗るので、キーボードのフォーカス枠（`:focus-visible` の 3px）を戻している。
- 承認された色は、文字のコントラストが WCAG AA の 4.5:1 に届かない組み合わせがある（独立レビューの計測：明るいテーマの件数 `#4f8fd6` 3.37・`#5f9a46` 3.39・`#c8574f` 4.26、暗いテーマの `#c8574f` 3.92、評価ボタンの白文字 難しい 3.15・簡単 4.08・もう一度 4.26）。件数は太字で、評価ボタンはキーと `aria-label` でも区別できるので本人の承認値のままにした。明るいテーマ用に濃い色を変数で上書きするかは本人の判断待ち。
- 上部の ← などアイコンボタンが無効（保存中・保存失敗中）のときは薄く表示する。

## 2. 階層: 主役は1つ、補助は控えめ

- `mod-cta` は各状態で最大1つ（完了画面は無し）。復習画面の出題中は「答えを表示」、保存失敗中は「もう一度保存する」だけ。答え表示中は `mod-cta` を付けず、4つの評価ボタンをそれぞれの色で塗る（LEV-321 の例外。以前の「無彩色＋普通だけ強調」はやめた）。キーボードの既定は従来どおり「普通」へのフォーカス。
- 評価ボタンは 1〜4 の順。スキップ・元のノートを開く・デッキに戻るは歯車のメニューに置く（スキップはキー `S` も使える）。デッキに戻るは上部左の ← でもできる。
- 同じ情報を2回出さない。復習画面ではタグは上部中央の進捗表示（`#タグ | 現在/全体`）だけに出し、モーダルのタイトルは使わない。「残り N 枚」の文字は出さない。デッキ選択の上部は「デッキ」・⋯・× だけで、候補の抽出・状態・保存先の説明は ⋯ のメニューに入れる。
- 内容を最も大きく読む対象にする。問題と答えは同じ文字サイズで、それぞれに小さな見出し「問題」「答え」を付け、細い区切り線で分ける。評価ボタンは区切り線の下の下部に固定し、本文（問題と答え）は答えの領域を広く取って（最小の高さ `min(380px, 45vh)`）、長いときは本文の中でスクロールする。

## 3. ショートカット表示

- キー操作できるボタンとメニュー項目は、同じ形のキーバッジ（`.kioku-review-key`）を付ける。評価ボタンでは右下、「答えを表示」とメニューの「スキップ」ではラベルの後ろ。括弧書き「（S）」と混在させない。
- バッジは `aria-hidden="true"` にして読み上げ対象から外し、ボタンに `aria-keyshortcuts` を付ける。評価ボタンは `aria-label` にもキーを含めるので、ショートカットを読み上げる支援技術ではキー名が2回聞こえることがある（実機の読み上げは未確認）。
- 評価ボタンは「ラベル」と「次回の間隔」を2段で示し、キーは右下に置く。`aria-label` には「普通（キー 3）：次回 3日後」のように全部を含める。

## 4. 状態の表示

- 保存中・保存失敗は、下部の評価ボタンの下の状態行（`.kioku-review-status`）に出す（評価を押した直後にボタンの位置が動かないように）。保存中は控えめな色、失敗は `--text-error`。失敗時の再試行ボタンは同じ行の末尾に置き、フォーカスを移す。
- 保存中・失敗中は評価ボタン・← ・歯車のメニュー項目（スキップを含む）を無効にする（`disabled`）。見た目だけでなく `handleKey` 側でも受け付けない。歯車のメニュー自体は開閉できる。
- 読み取り専用などの注意は `--text-warning` で上部に出す。
- 対象がない操作は無効表示で残さず、出さない（例: 完了画面ではカードに依存するメニューを出さない）。

## 5. キーボードとフォーカス（変更してはいけない約束）

- キー入力は `ReviewScreen#handleKey` の1経路だけで処理する。Space/Enter はフォーカス中の Kioku ボタンに対して1回だけ働き、ネイティブのクリックと二重に発火しない。キーリピート・IME 変換中・修飾キー付きは無視する。
- Escape はメニューが開いていればメニューだけを閉じてフォーカスを歯車に戻し、閉じていればモーダルを閉じる（Obsidian の Scope 経由。二重発火させない）。
- 描画のたびに、その状態の主要操作へフォーカスを置く。主要操作が押せない間（保存中、読み取り専用で答えを表示中など）は画面ルート（`tabIndex = -1`）に置き、フォーカスをモーダルの外へ逃がさない。
- 答え表示中の「主要操作」は「普通」（色付きで `mod-cta` は無いが、キーボードの既定として残す）。
- 例外: メニューを開いた直後は先頭のメニュー項目「スキップ」（無効なら主要操作、それも無ければ歯車）、メニューを閉じた直後は歯車に置く。完了画面は強調する主要操作が無いので、最初の「今日だけ あと N 枚」、無ければ「デッキ選択に戻る」に置く（処理中は画面ルート）。デッキ選択は最初の行、行が無ければ ⋯ に置く。
- デッキ選択の ⋯ は Obsidian の `Menu`（キー操作と Escape は Obsidian が扱う。macOS の既定ではネイティブメニュー）。
- これらは `tests/ui/review.test.mjs` の回帰テストで固定している。見た目の変更でクラス名や DOM 順を変えるときはテストも更新する。

## 6. 幅と長文

- モーダル幅は画面ごとに `min(<幅>, <画面比>)` で決める（起動 `min(32rem, 90vw)`、候補選択 `min(48rem, 92vw)`、デッキ選択 `min(560px, 100%)`、復習 `min(820px, 100%)`。デッキ選択と復習は同じモーダルで、復習中はルートに `kioku-is-reviewing` を付けて幅を切り替える）。
- 評価ボタンのラベルは途中で折り返さない（`white-space: nowrap`）。評価ボタンは復習画面の幅（コンテナクエリ `kioku-review`）が 27rem 以下なら 2 列×2 段に切り替える。
- 問題文・答えは `overflow-wrap: anywhere` で折り返し、長いときは本文（`.kioku-review-body`）の中でスクロールする。上部と下部は固定。デッキ名が長いときは行の中で省略記号で切る。

## 7. 確認のしかた

- UI の変更は `npm run check` に加え、専用 Vault の実機（`harness:launch` / `harness:quit`）で明/暗・長文・狭幅を見て `artifacts/` に証跡を残す。モックやファイル検査の成功を実機成功と呼ばない。
- 実機確認は合成データだけを使い、利用者の Vault や Obsidian には触れない。
