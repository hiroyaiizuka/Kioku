# Kioku 候補選択画面の実装

## 概要

このドキュメントは、Kioku の候補選択画面（M1 の中核機能）の実装を説明します。この画面は、ノート内の明示的な Q/A を抽出し、ユーザーが採用・編集・破棄を選択できる中央ポップアップです。

## 実装状況

- **実装コミット**: 4be240d (LEV-275: M1 明示 Q/A の候補選択と元メモ保存)
- **テスト結果**: 382 テスト全て合格
- **ファイル構成**:
  - `src/ui/candidate-modal.ts` - メインのモーダル UI
  - `src/ui/extract.ts` - ノートからの候補抽出
  - `src/cards/parser.ts` - Q/A の解析
  - `src/cards/writer.ts` - ノートへの書き込み
  - `styles.css` - UI スタイル

## UI 構成要素

### 1. モーダルヘッダー
- タイトル: 「問い・答えの候補 — [ノート名]」
- スコープ表示: ノート全体 または 選択範囲

### 2. サマリーセクション
```
[スコープ]の明示した問い・答え：N 件（未採用 M 件）。
残したものだけ元ノートに ID を追記します。
見送る・閉じるでは何も書き込みません。
```

### 3. 候補カード（各候補ごと）

#### メタデータ行
- 行番号: 「N 行目」
- ステータス: 未採用 / 採用済み / ID 重複のため採用不可 / 既存の block ID があるため採用不可
- カード ID (採用済みの場合): `^kioku-...`

#### 原文表示
```
原文
[元のブロックテキスト]
```

#### 編集フィールド（未採用の場合）
```
問い（編集可能）
[編集可能なテキストエリア]

答え（編集可能）
[編集可能なテキストエリア]
```

#### アクションボタン
- **残す** (mod-cta スタイル): 候補を元ノートに保存
- **見送る**: この候補をポップアップから削除（ノートには何も書かない）

> **注**: 以前のラベルは「採用」「破棄」でした。現在の UI では「残す」「見送る」と表示され、フィールドラベルに「（編集可能）」を明示しています。

#### 状態表示
- 保存中: 「保存しています…」
- 確認中: 「保存を確認しています…」
- 回復中: 「別の画面の保存と重なりました。ノートが落ち着くのを待って、もう一度保存します…」

### 4. 注記とガイダンス

#### 空行挿入の注記
直後に空行がない候補には:
```
直後に空行がないため、採用時にこのブロックの後へ空行を1行追加します
（ID を段落末に置くため。原文の文字は変えません。
改行コードは Obsidian の編集画面の扱いに従います）。
```

#### 警告表示
- 採用済みカードと同じ内容: 「採用済みカードと同じ内容です。」
- その他の警告（AI 生成候補の場合）

### 5. フッター
- **閉じる**ボタン: ポップアップを閉じる（保存済みの採用だけが残る）

## 主要な機能

### 候補の抽出
- 行頭の `Q:` / `問:` (全角コロン・全角Ｑも可) から始まるブロック
- `A:` / `答:` を含む行以降が答え
- 空行・見出し・次の問いでブロック終了
- コードブロック・`%%` コメント・Excalidraw データは除外

### 編集機能
- 問いと答えを自由に編集可能
- 編集内容は再レンダリング後も保持
- 編集した内容で「残す」を選ぶと `%%kioku-edit:...%%` コメントが追加

### 採用処理（「残す」ボタンの動作）
1. **書き込み前の原文照合**: 抽出時の原文が現在のノートにあることを確認
2. **Canvas ガード**: Canvas に埋め込まれているノートへの書き込みを拒否
3. **Editor / Vault.process 経路の選択**: 
   - 編集中のビューがあれば Editor.transaction
   - 閉じている/Reading view なら Vault.process
4. **ディスク確認**: 書き込み後 3 秒で ID がディスクにあることを確認
5. **1回だけの回復**: 他のビューの保存で上書きされた場合、ノートが落ち着いてから再試行

### 保存の安全性
- 同時に1つの保存だけを処理（他のボタンは無効化）
- 書き込み成功の確認後のみ「採用しました」を表示
- 確認前にポップアップを閉じると Notice で警告
- オフセット管理: 保存後、後続の候補のオフセットを自動調整

### Undo/Redo 対応
- 1回の保存（「残す」）= 1回の Undo ステップ
- Editor.transaction による書き込みで自然に実現

## デザイン原則

### Obsidian ネイティブな見た目
- Obsidian の CSS 変数を使用: `--background-modifier-border`, `--text-muted`, `--radius-m` など
- 標準的なフォントサイズとスペーシング
- mod-cta クラスによる主要アクションの強調

### 情報の近接性
- 問い・答え・元の原文を1つのカードにまとめて表示
- メタデータ（行番号、ステータス）は控えめに上部に配置
- 編集フィールドは原文の直下

### 明確なアクション
- 「残す」ボタンは mod-cta (Call to Action) スタイル
- 「見送る」ボタンは標準スタイル
- 保存中はボタンを無効化し、状態を明示
- 各アクションの結果を Notice で通知

### スクロール可能な長いリスト
- `.kioku-candidate-list` は `max-height: 65vh` で固定
- `overflow-y: auto` で縦スクロール
- 再レンダリング時にスクロール位置を保持
- テキストエリアのフォーカスと選択範囲も保持

## 既知の制約

1. **Canvas 埋め込み**: Canvas にファイルノードとして埋め込まれているノートへの書き込みは拒否（独自 editor による上書きを回避）
2. **ホバー popover**: ページプレビューの遅れた保存は1回だけ回復を試行（連続する打鍵中は失敗）
3. **改行コード**: Editor 経路では Obsidian が LF に正規化（仕様として受け入れ）
4. **複数行の `%%` / `$$`**: インラインコード内の記号で個数判定がずれる場合、保守的に候補を減らす（誤って書き込む方向には働かない）
