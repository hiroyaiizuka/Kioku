# Kioku

Kioku は、Obsidian 上の学習メモからフラッシュカードを作り、復習することを目指す **PC 専用**プラグインです。

> 現在は M2 開発版に M3 の一部を加えたものです。ノートに自分で書いた Q/A を候補として確認・編集し、採用したものだけ元ノートに印を付けられます（M1）。採用したカードは、タグで決まるデッキから問い → 答え → 4段階の評価で復習でき、次回の日程は FSRS で決まります（M2）。**AI による候補作成は一部だけ実装しました（M3 部分実装・実機未確認）。** 既定はオフで、設定したときだけ動きます。M2 と M3 は専用テスト Vault での実機確認がまだ終わっていません。実機確認が完了するまでは、動作確認済みとは扱いません。

## Q/A の書き方

行頭に問いと答えの印を書いたブロックが候補になります。半角/全角コロン、`- ` で始まる箇条書きも使えます。

```text
Q: 光合成とは？
A: 光エネルギーで糖を作る反応

問：細胞の基本単位は？
答：細胞
```

- 答えは次の空行・見出し・次の `Q:` まで続きます（複数行・箇条書き可）。
- コードブロック、`%%` コメント、HTML コメント、`$$` 数式ブロック、frontmatter、Excalidraw の描画データ（`# Excalidraw Data` 以降）は対象外です。

## 使い方

1. Q/A を書いたノートを開きます（一部だけ対象にしたい場合は範囲を選択）。
2. コマンドパレットの「Kioku: 開いているノート・選択範囲から問い・答えの候補を抽出」、デッキ選択画面（左 ribbon「フラッシュカード」）の ⋯ メニュー「問い・答えの候補を抽出」、状態ポップアップ（コマンド「Kioku: フラッシュカード（状態）」）の「候補を抽出」ボタン、またはファイルメニューの「Kioku：問い・答えの候補を抽出」を使います。
3. 中央のポップアップで原文を確認し、必要なら問い・答えを編集して「採用」、不要なら「破棄」します。

## ノートへの保存

- 書き込むのは「採用」を押したときだけです。起動時、ポップアップを開いたとき、「破棄」や閉じたときは何も書きません。
- 採用すると、そのブロックの最終行末に ` ^kioku-xxxxxxxxxx`（Obsidian の block ID）を追記します。元の問い・答えの文字は書き換えません。
- ブロックの直後に空行がなく文が続いている場合（次の `Q:` や `---` など）は、ID が段落の末尾になるよう、ブロックの後に空行を1行追加します（箇条書きの項目が続く場合は追加しません）。ポップアップの該当候補にその旨が表示されます。追加するのは ID と改行だけで、元の文字は変えません。
- 改行コードは Obsidian の扱いに従います。開いているノートは Obsidian の編集画面が LF で保存するため、CRLF のノートも保存時に全体が LF になります（Kioku を使わなくても Obsidian が同じ動作をします）。閉じたノートへファイルメニューから採用した場合は、そのブロックの改行コードのまま追記します。
- ポップアップで編集した場合は、元の文はそのまま残し、直後に `%%kioku-edit:kioku-…` 〜 `%%` の編集記録（Reading view では非表示）を追加します。空行・見出し・コードブロックの区切り・`$$`・HTML コメントなどを含む編集は保存できず、理由が表示されます。
- 保存直前に原文を照合し、外部で変更されていた場合は書き込まずに理由を表示します。Source / Live Preview で開いているノートへの採用はエディタの Undo で戻せます。Reading view だけで開いている場合や閉じたノートはファイルへ直接書き込み、Reading view は自動で再表示されます（この場合 Undo はできないので、ID を消して取り消します）。「採用しました」は、ファイルに ID が保存されたことを確認してから（約3秒後）表示します。それまではカードに「保存を確認しています…」と表示され、確認できなかったときは理由を表示してカードを未採用に戻します。確認中にポップアップを閉じると「保存の確認前に閉じました。もう一度抽出して採用済みか確認してください。」と1回だけ表示します（プラグインの無効化・Obsidian の終了時は表示しません）。
- 開いている Canvas に埋め込まれているノートには採用できません（Canvas 側の編集が後から上書きして ID が消えるため）。Canvas を閉じてから採用してください。ページプレビューのホバーなど Kioku が検出できない画面で同じノートを編集していて、その画面の保存で ID が消えた場合は、ノートの変更が落ち着くのを待って、原文を確かめ直したうえで1回だけ自動で保存し直します（「別の画面の保存と重なりました…」と表示）。それでも残らない場合や原文が変わっていた場合は、成功とは表示せず理由を表示します。
- 採用済み（`^kioku-` 付き）のブロックは再抽出しても「採用済み」と表示され、二重に採用されません。ID を消すと再び候補になります。
- 「破棄」はそのポップアップから外すだけで、ノートには記録しません。

## 復習（デッキと間隔反復、M2）

### デッキ

- ノートにトリガータグ（既定は `#kioku`。設定で変更・複数指定できます）を付けると、そのノートの採用済みカード（`^kioku-…` 付きのブロック）がデッキに入ります。タグは本文でも frontmatter の `tags` でも構いません。タグはノート全体に効きます。
- デッキ選択には、ノートに書いたタグごとに1行ずつ、階層をつけずに並びます（タグ名順。`#kioku/医学/生理` → 「#医学/生理」。トリガータグが1つのときは `kioku/` を省きます）。書いたタグの親（例: `#医学`）は、そのタグを書いたノートがあるときだけ行になり、子のカードも含みます。`#kioku` だけを付けたノートがあると「#kioku」の行（全カード）が出ます。タグの大文字小文字は区別しません。コードブロック・`%%` コメントなどの中のタグは数えません。
- トリガータグのないノートのカードは出題されず、デッキ選択に枚数だけ表示されます。
- 同じ `^kioku-…` が複数のノートにある場合（同期の競合ファイルや複製など）、内容が同じなら1枚として出題し、内容が違えば出題せず両方のパスを表示します。
- 2つ以上のデッキに入っているカードも、1回の復習で出るのは1回だけです。日程はカードごとに1つなので、あるデッキで評価すると他のデッキでも同じ日程になります。

### 復習の流れ

1. 左 ribbon「フラッシュカード」（またはコマンド「Kioku: デッキを選んで復習」）で中央にデッキ選択が開きます。各デッキに「新規」（まだ一度も評価していないカード）/「学習中」（期日が来たカードのうち、前回「もう一度」を押したもの）/「復習」（それ以外で期日が来たカード）の3つの数が出ます。⋯ メニューから候補の抽出・状態・記録の保存先の説明を開けます。
2. デッキを選ぶと問いが表示されます。上部にタグと進み具合（例: `#医学/生理 | 1/3`）、左の ← でデッキ選択に戻れます。`Space` または `Enter` で答えを表示し、下の「もう一度 / 難しい / 普通 / 簡単」（キー `1`–`4`）で評価します。各ボタンに次回までの日数が出ます。
3. 「スキップ」（`S`、または右上の歯車のメニュー）は何も記録せず、その回の復習から外すだけです。次に開いたときにはまた出ます。歯車のメニューには「元のノートを開く」「デッキに戻る」もあります。
4. 途中で閉じても（`Escape` など）、評価済みのカードは保存済みです。続きから再開する機能はなく、次に開いたときに期日の来たカードと新規カードから作り直されます。
5. 新規カードは1日 20 枚まで（設定で変更・上限なしも可）です。上限で出なかった分はデッキ選択の一覧の下（「新規は残り N 枚が明日以降」）と終わりの画面に表示され、終わりの画面の「今日だけ あと10枚 / 20枚」でその日だけ増やせます（まだ一度も評価していないときは保存せず、評価せずに閉じると元に戻ります）。期日のカードには上限がありません。
6. 日付の切り替えは朝 4 時（設定で変更可）です。0 時〜3 時 59 分の復習は前日分として数えます。同じ日に同じカードがもう一度出ることはありません（「もう一度」でも次回は翌日以降）。
7. 答えを表示する前は、問いの中の埋め込み（`![[…]]`、`![…](…)` などの画像、`<img>`・`<iframe>`）はリンクや文字として表示し、コードブロックも dataview などで処理せずそのまま表示します（埋め込み先で答えが見えないようにするため）。

日程の計算には FSRS（ts-fsrs 5.4.2、目標の記憶率 90%）を使います。詳しくは [FSRS とは](docs/fsrs.md) を参照してください。

### 学習記録の保存

- 評価の記録と日程は Vault 内の `Kioku/` フォルダ（設定で変更可）に保存します。ノート本文は書き換えません。
  - `Kioku/history-<年>.jsonl`：評価1回ごとに1行追記する記録（正本）。スキップは記録しません。
  - `Kioku/state.json`：各カードの現在の日程（記録から作り直せる控え）。`Kioku/state.json.bak` は直前の控えのコピーです。
- デッキ選択を開いたり閉じたりするだけでは何も作らず、書き込みません。`Kioku/` は最初に評価したときに作られます。
- 問い・答えを編集しても、`^kioku-…` が同じならそのカードの日程と記録はそのまま残ります（記録には評価時の内容のハッシュが残ります）。
- `Kioku/` を削除・移動すると日程と記録が失われます。Obsidian Sync では既定で `.json` / `.jsonl` は同期されません（Kioku は PC 1台での利用を前提にしています）。
- データフォルダの設定を変えても、ファイルは移動しません。古いフォルダにデータがあり新しいフォルダに無い場合、設定は変更されず「古いフォルダ（…）にデータがあります。移動してから変更してください」と表示されます。先に Obsidian の外でフォルダを移動してから変更してください。

### 記録が読めないときの復旧

Kioku はデータを失わないよう、読めないファイルを上書きしません。その場合はデッキ選択に理由が表示され、評価できない「読み取り専用」になります。

1. Obsidian を閉じ、`Kioku/` フォルダごとコピーしてから作業します。
2. 日程ファイル `state.json` が壊れたときは、`state.json.bak` を `state.json` に戻すか、`state.json` を削除します。次に開いたとき、評価の記録（`history-<年>.jsonl`）から日程が作り直されます。削除して失われるのは、その日の「今日だけ あと N 枚」の追加分だけです。
3. 評価の記録の最後の1行だけが途中で切れているときは、その行が日程ファイルにまだ反映されていたかどうかで扱いが変わります。
   - まだ反映されていない場合（評価の保存中に Obsidian が終了したときなど、通常の形）：デッキ選択に「最終行（N 行目）が途中で切れています」と「不完全な最終行を退避して続ける」ボタンが出ます。押すと、その1行を `history-<年>.jsonl.broken` に移して続けられます（その行の評価は失われます）。押さなければ何も書き換えません。
   - 既に反映されていた場合（あとからファイルが外部で壊された場合）：「…反映済みとしている行より短くなっています」と表示され、ボタンは出ずに読み取り専用になります。Obsidian を閉じ、`Kioku/` をコピーしてから、切れた行を `history-<年>.jsonl.broken` に移し（または消し）、`state.json`・`state.json.bak`・`state.json.tmp` を削除して開き直してください。記録から日程が作り直されます。
4. それ以外の行が壊れているときは、ファイル名と行番号が表示されます。その行をテキストエディタで `history-<年>.jsonl.broken` に移し、`state.json` と `state.json.bak`（と残っていれば `state.json.tmp`）も削除してから（記録から作り直されます。6. を参照）、Obsidian を開き直してください。
5. 新しい版の Kioku で書かれたデータ（未知の `schemaVersion`）も読み取り専用になります。
6. 日程ファイル（`state.json` が無いときは `state.json.tmp` や `state.json.bak`）が反映済みとしている記録ファイルが無い・短くなっている場合も、残りの日程を失わないよう読み取り専用になります。記録ファイルをバックアップから戻すか、2. の手順で `state.json` を戻してください。
7. プラグイン設定の学習データのフォルダが読めない・使えない値になっている場合、デッキ選択は開かず、設定画面も変更できません（既定のフォルダで新しく始めることはしません）。Obsidian を閉じ、`.obsidian/plugins/kioku/data.json` の `dataFolder` を正しいフォルダ名（例 `"Kioku"`）に直してください。

### 設定

Obsidian の設定 → Kioku で変更できます（設定はプラグインの `data.json` に保存され、学習記録とは別です）。

- トリガータグ（既定 `#kioku`、カンマ区切りで複数）
- 1日の新規カード数（既定 20、上限なしも可）
- 日付の切り替え時刻（既定 4:00）
- 学習データのフォルダ（既定 `Kioku`、上記の変更ガードあり）

## AI による候補作成（M3 部分実装・実機未確認）

**既定はオフです。** 生成について Obsidian 上での実機確認（E2E）はまだで、品質も評価していません。速さは、Obsidian の外で、限られた条件の試験だけを測りました（下記。記録は `artifacts/lev-277/timeout-investigation/RESULTS.md`）。外部の AI サービスには接続していません。設計と実装状況は [M3 設計](docs/m3-design.md)（§16）。

- 設定 → Kioku →「AI による候補作成」で「AI を使う」をオンにし、ローカルのサーバー（Ollama・llama.cpp・LM Studio。OpenAI 互換）とモデル名を入力します。接続先はホストとポートまでです（`/v1` などのパスは付けません）。推奨モデルは実測後に案内します。
- サーバーが Ollama のときは、モデルの「思考」を止めて送ります（`reasoning_effort: "none"`）。思考する種類のモデルは、止めないと答えの前に長く考え、時間内に終わらないためです。サーバーがこの指定を拒んだ場合（その指定についての HTTP 400）に限り、残りの時間の範囲で指定を外してもう一度だけ送ります。ほかの理由の 400 では送り直しません（本文を二度送らないため）。llama.cpp・LM Studio では何も変えません。
- 生成の時間切れは 60 秒（既定）のままです。手元の試験（Ollama 0.34.2・gemma4:26b・合成ノート約 520 字）の結果は次のとおりです。
  - Kioku と同じ経路（OpenAI 互換の `/v1/chat/completions`、思考を止める指定あり）：45.5 秒（load average 83、モデルの再読み込みを含む）、66.6 秒（load 267）、95.6 秒（load 260）。負荷が低いときの、モデルを読み込み済みの計測はしていません。
  - 31〜48 秒という結果は、Ollama 独自の API（`/api/chat`、`think: false`）での計測です。Kioku の経路ではありません。
  - 思考を止めても **60 秒以内に安定して終わることは確かめていません**。モデルによっても変わります。
- 候補ポップアップの「AI で候補を作る」を押したときだけ通信します。起動時や、設定タブ・ポップアップを開いただけでは通信しません。
- AI は本文から「1つの事実＋原文の引用」を元に問い・答えの候補を作ります。引用が原文にそのまま見つからない候補は除外し、件数だけ表示します。枚数は決めておらず、根拠が無ければ 0 件です（上限 20 件）。
- 判定は Jev（TypeSafe AI、外部・有料）か「判定なし」です。Jev のキーと送信への同意が無ければ、候補は「未判定（Jev 未設定）」などと表示されます。Jev は主に英語で学習されたモデルで、日本語では精度が下がる可能性があります（未実測）。
- 採用は人が行います。生成した候補を採用すると、引用元の段落（箇条書き・表・引用・callout の中ならその全体）の直後に、空行を挟んで `Q:`/`A:` ブロック（`^kioku-…` 付き）と、引用の記録 `%%kioku-src:… %%`（閲覧表示では見えません）を追加します。原文の文字は変えません。
- Excalidraw のノートでは AI で候補を作りません。

### 外部への送信とキーの保存

- 外部（このパソコンの外。Jev、`localhost` 以外の接続先〈`0.0.0.0` を含む〉、名前が `cloud` で終わるモデル〈Ollama の cloud モデルなど。サーバーの種類によらず外部扱い〉）に送るのは、送信先ごとに設定画面で同意したときだけです。接続先・サーバー・モデルを変えると同意は取り消され、元の値に戻しても同意し直しが必要です。毎回、送信先・文字数・概算費用を表示し、「送信して作る」を押すまで送りません。
- 送るのは本文（コードブロック・`%%` コメント・HTML コメント・数式ブロック・frontmatter を除く）か選択範囲だけで、ノート名・ファイルパス・Vault 名は送りません。1回の上限は 8,000 字です。ローカルのサーバーが別のサービスへ中継する設定なら外部に送られますが、Kioku からは分かりません。
- キャンセルしても、送信済みの分は送信先で処理・請求されることがあります（Obsidian の通信 API は送信を取り消せません）。サーバーが応答しないまま残った要求は、Kioku を再読み込み（無効化→有効化か Obsidian の再起動）するまで同時実行の枠を使い続け、その間は「前の要求の完了を待っています」と表示されます。
- **API キーは Vault の設定フォルダ内 `plugins/kioku/data.json` に暗号化せずに保存されます。** 同期・Git・バックアップで Vault と一緒に複製され、他のプラグインからも読めます。利用上限を設定した専用のキーを使ってください。M3 から M2 版の Kioku に戻して設定を保存すると、AI の設定（キーと同意）は消えます。

## 開発ビルドを専用 Vault で確認する

一般利用者向け Release はまだありません。開発者は Node.js 22.22.3 で `npm ci`、`npm run check`、初回だけ `npm run harness:prepare` を実行し、`npm run harness:launch`（macOS）でプロジェクト内の専用 Vault（既定 `test-vault/`）だけを開く専用 Obsidian を起動します。普段の Obsidian は開いたままで構いません。終了は `npm run harness:quit` です。既存 Vault へ自動導入しないでください。詳しくは [開発手順](docs/development.md) と [ハーネス](docs/harness.md) を参照してください。

## 対応範囲

- Obsidian 1.8.7 以上のデスクトップ版を宣言しています。
